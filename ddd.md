# Domain-Driven Design (DDD) — Alumni Tracking System

This document defines the domain model, entities, validation rules, business constraints, and bounded contexts for the Alumni Tracking System.

---

## 1. Domain Model Overview

The Alumni Tracking System operates within the **Alumni Management** domain. Its primary purpose is to manage graduate records, facilitate networking through job postings, and organize alumni events. The system follows a layered MVC architecture with clear separation between domain logic (Model), presentation (View), and request handling (Controller).

```
┌─────────────────────────────────────────────────┐
│              Alumni Management Domain            │
│                                                   │
│  ┌───────────┐  ┌───────────┐  ┌───────────┐    │
│  │  Alumni    │  │   Job     │  │   Event   │    │
│  │  Context   │  │  Posting  │  │  Context  │    │
│  │           │  │  Context  │  │           │    │
│  └───────────┘  └───────────┘  └───────────┘    │
└─────────────────────────────────────────────────┘
```

## 3. Entity Definitions & Validation Rules

### 3.1 Alumni / User Entity (Core — Implemented)

The central entity representing a graduated alumnus in the system.

**Schema:**

| Field | Type | Required | Constraints | Description |
|:------|:-----|:---------|:------------|:------------|
| `id` | Number | Auto-generated | Auto-incremented, unique, positive integer | Unique identifier |
| `name` | String | ✅ Yes | Min 1 char, max 50 chars, non-empty after trim | First name of the alumnus |
| `surname` | String | ✅ Yes | Min 1 char, max 50 chars, non-empty after trim | Last name of the alumnus |
| `age` | Number | ✅ Yes | Integer, range 0–120, non-negative | Current age of the alumnus |
| `birthday` | String | ✅ Yes | Format: `YYYY-MM-DD`, must be a valid calendar date, cannot be in the future | Date of birth |

**Validation Rules:**

1. **name**: Required. Must be a non-empty string. Maximum 50 characters. Leading/trailing whitespace should be trimmed.
2. **surname**: Required. Must be a non-empty string. Maximum 50 characters. Leading/trailing whitespace should be trimmed.
3. **age**: Required. Must be a valid non-negative number (integer). Accepted range: 0 to 120.
4. **birthday**: Required. Must follow the `YYYY-MM-DD` date format. Must represent a valid calendar date.
5. **id**: Auto-generated by the system. Cannot be set or overridden by the client. Always a positive integer.

**Business Rules:**

- All four fields (`name`, `surname`, `age`, `birthday`) are mandatory for `POST` (create) and `PUT` (full update) operations.
- For `PATCH` (partial update), only the provided fields are validated; missing fields retain their current values.
- The `id` field is immutable — it cannot be changed after creation.
- Duplicate names are allowed (two alumni can share the same name).

### 3.2 Job Posting Entity (Planned)

Represents a career opportunity posted by or for alumni members.

**Schema:**

| Field | Type | Required | Constraints | Description |
|:------|:-----|:---------|:------------|:------------|
| `id` | Number | Auto-generated | Auto-incremented, unique, positive integer | Unique identifier |
| `title` | String | ✅ Yes | Min 1 char, max 120 chars, non-empty after trim | Job title / position name |
| `company` | String | ✅ Yes | Min 1 char, max 100 chars, non-empty after trim | Company or organization name |
| `city` | String | ❌ No | Max 80 chars | City / location of the job |
| `description` | String | ❌ No | Max 2000 chars | Detailed job description |
| `salary` | Number | ❌ No | Must be non-negative if provided | Salary amount (optional) |
| `type` | String | ❌ No | Enum: `full-time`, `part-time`, `contract`, `internship`, `remote` | Employment type |
| `postedBy` | Number | ✅ Yes | Must reference a valid Alumni `id` | Alumni member who posted the job |
| `createdAt` | String | Auto-generated | ISO 8601 datetime | Timestamp of creation |

**Validation Rules:**

1. **title**: Required. Must be a non-empty string after trimming. Maximum 120 characters.
2. **company**: Required. Must be a non-empty string after trimming. Maximum 100 characters.
3. **city**: Optional. If provided, maximum 80 characters.
4. **description**: Optional. If provided, maximum 2000 characters.
5. **salary**: Optional. If provided, must be a non-negative number (≥ 0).
6. **type**: Optional. If provided, must be one of the predefined enum values.
7. **postedBy**: Required. Must reference an existing Alumni record by `id`.

**Business Rules:**

- A job posting must always be associated with a valid alumni member (`postedBy`).
- When an alumni record is deleted, all their associated job postings should be soft-deleted or archived.
- Job titles should not contain HTML or script tags (sanitization required).

### 3.3 Event Entity (Planned)

Represents an alumni event, reunion, or meetup.

**Schema:**

| Field | Type | Required | Constraints | Description |
|:------|:-----|:---------|:------------|:------------|
| `id` | Number | Auto-generated | Auto-incremented, unique, positive integer | Unique identifier |
| `title` | String | ✅ Yes | Min 1 char, max 150 chars, non-empty after trim | Event title |
| `date` | String | ✅ Yes | Format: `YYYY-MM-DD`, must be a valid date, must be in the future for new events | Event date |
| `time` | String | ❌ No | Format: `HH:MM` (24-hour) | Event start time |
| `location` | String | ❌ No | Max 200 chars | Venue / location |
| `description` | String | ❌ No | Max 1000 chars | Event details and agenda |
| `organizer` | Number | ✅ Yes | Must reference a valid Alumni `id` | Alumni member organizing the event |
| `capacity` | Number | ❌ No | Positive integer if provided | Maximum number of attendees |
| `createdAt` | String | Auto-generated | ISO 8601 datetime | Timestamp of creation |

**Validation Rules:**

1. **title**: Required. Non-empty string after trimming. Maximum 150 characters.
2. **date**: Required. Must follow `YYYY-MM-DD` format. Must be a valid calendar date. New events must have a future date.
3. **time**: Optional. If provided, must follow `HH:MM` 24-hour format.
4. **location**: Optional. Maximum 200 characters.
5. **description**: Optional. Maximum 1000 characters.
6. **organizer**: Required. Must reference an existing Alumni record.
7. **capacity**: Optional. If provided, must be a positive integer (≥ 1).

**Business Rules:**

- Past events cannot be created (date validation).
- Event capacity cannot be reduced below the current number of registered attendees.
- An event must have at least one organizer who is a valid alumni member.

## 5. Aggregates

### Alumni Aggregate (Root)
- **Root Entity:** Alumni / User
- **Value Objects:** Name (name + surname), Age, Birthday
- **Associated Entities:** Job Postings (one-to-many), Event Registrations (many-to-many)
- **Invariants:**
  - An alumni record must always have a valid name, surname, age, and birthday.
  - Deleting an alumni should cascade to their job postings and event registrations.

### Job Posting Aggregate
- **Root Entity:** Job Posting
- **Value Objects:** Salary, Location (city)
- **References:** Alumni (postedBy)
- **Invariants:**
  - A job posting must always reference a valid alumni member.

### Event Aggregate
- **Root Entity:** Event
- **Value Objects:** EventDate (date + time), Location
- **References:** Alumni (organizer), Attendees (many-to-many)
- **Invariants:**
  - An event must have a valid future date at creation time.
  - Attendee count must not exceed capacity.

## 7. Error Handling Strategy

All validation errors should return structured responses with:
- **HTTP 400** for invalid input / missing required fields
- **HTTP 404** for non-existent resources
- **HTTP 500** for internal server errors
- Clear, human-readable error messages identifying which field(s) failed validation
